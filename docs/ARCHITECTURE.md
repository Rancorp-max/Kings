# Architecture (as found, before the PartyDeck work)

1. **Stack:** no build step. Vanilla HTML/CSS/JS in `public/` (`index.html`, `styles.css`, `app.js` ~1k lines) served as static files; Google Fonts + PeerJS + qrcodejs from CDNs.
2. **Deploy:** Vercel project `kings-gamma.vercel.app`, zero-config: `public/` is the output directory, `api/**/*.js` are CommonJS Node serverless functions. Root `index.html` just redirects to `public/` for other hosts.
3. **Env vars:** `REPLICATE_API_TOKEN` (set on Vercel; used by the legacy `api/ai/*` Replicate helpers, which the current UI does not call). No database, no auth, no payments.
4. **Rooms & sync:** peer-to-peer over WebRTC via PeerJS and its free public broker. The host's browser registers peer id `kingscup-v2-<CODE>` (4 letters) and is the authoritative game server; guests `peer.connect()` to it.
5. **Protocol:** guests send intents (`hello`, `draw`, `pick`, `category`, `rule`, `react`, `leave`); the host validates, mutates state and broadcasts the whole public state (`{t:'state'}`) after every change. Heartbeats every 4 s, 14 s timeout, offline players' turns auto-skip after 15 s.
6. **Resilience:** host state + shuffled deck persisted in `localStorage` (`kc_host_<CODE>`); `kc_session` lets host or guest auto-rejoin after a refresh; guests retry 20× on disconnect. `?transport=local` swaps in a BroadcastChannel transport for same-browser testing.
7. **Avatars/profiles:** emoji avatar + colour + name chosen on the profile screen, stored in `localStorage` (`kc_profile`, with a stable random player id).
8. **Deck:** a shuffled 52-card deck lives only on the host; each rank maps to a fixed rule (A Never Have I Ever … K King's Cup). 2 and 8 let the drawer pick a player; J picks a category; K adds a house rule; the 4th King (or an empty deck) ends the game.
9. **Gentle mode:** host toggle (default on) that words rules as "sip/penalty" instead of "drink"; applied when rendering rule text.
10. **House rules:** Question Master (last Queen), mates (8s) and King rules are kept in state and listed in a collapsible panel; reactions are broadcast as transient `react` messages (not state).

# Architecture now (PartyDeck)

**Stack kept:** static vanilla-JS site in `public/` (now ES modules, still no build step) + Vercel Node functions in `api/`. New pieces use the defaults from the brief: **Firestore** (via `firebase-admin`), **Stripe**, and the **Anthropic SDK**. **React/Vite/Tailwind were not introduced:** the existing app is vanilla JS with no build, and adding one would have risked the live deploy for no user-visible gain. **Firebase Auth is not used:** hosts get a random host token per event (only its hash is stored), and `/admin` uses a password.

```
public/
  index.html, <6 SEO pages>.html, redeem/results/admin/privacy/terms/404.html   ← generated by scripts/build-pages.js
  play.html          the game (host + guests)
  js/main.js         boot, screens, lobby, end screen, menus
  js/host.js         authoritative game engine running in the host's browser (deck + quiz + keepsake)
  js/client.js       connection lifecycle (host/guest, reconnect, heartbeat)
  js/transport.js    PeerJS (WebRTC) + BroadcastChannel test transport
  js/setup.js        host setup: theme, mode, honouree, quiz builder, AI personalisation, plan/upgrade
  js/ui-deck.js, ui-quiz.js    screens      js/quiz-core.js  pure scoring (shared with tests)
  js/pdf.js          dependency-free PDF writer + keepsake layout
  js/themes.js, kings.js, decks/*.json      content (3 × 64 original cards + King's Cup)
  vendor/            self-hosted PeerJS + QRCode (MIT)
api/
  events.js          create/read/update the party ("event"): plan, attribution, games played, predictions
  checkout.js        Stripe Checkout session (or simulated checkout on non-production without keys)
  stripe-webhook.js  signature-verified, idempotent → marks the event paid + writes purchases/
  redeem.js          Etsy code → Party Pass (atomic single use via redemptions/{hash})
  generate-deck.js   Claude (claude-sonnet-5, JSON schema) → validate → blocklist + claude-haiku-4-5 check → retry once
  track.js           anonymous page-view counter;  admin.js  password-protected stats
  _lib/              db (Firestore | file store), events, stripe, codes, ai, admin, config, http
site.config.json     brand name, pricing, limits, AI models: the one file to rename or re-price
```

**Firestore collections:** `events`, `purchases` (eventId, theme, amountCents, method `stripe|etsy_code|mock`, source, referrer, createdAt), `ai_calls` (tokens + cost per call), `redemptions/{codeHash}`, `codes/{codeHash}` (optional, for `--db` minting), `pageviews/{day}`.

**Real-time:** unchanged model. The host's browser is the server and guests connect over WebRTC. Quiz answers are timed on the host's clock (no client clock trust). Correct answers never leave the host before the reveal. Keepsake notes stay on the host's device.

**Limits and gating:** the host's engine enforces the player cap (8 free / 40 Pass) and the number of playable AI questions/cards. The server enforces AI generations (1 free / 3 Pass). The keepsake watermark is applied client-side, so it's a nudge, not DRM.
